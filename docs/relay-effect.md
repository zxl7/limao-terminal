# 连板量能与承接

入口 `/effect`，新增模块放在当日双轴与历史模块之间。数据链：狸猫猎手 `feedback_matrix.py` 有效采集 → `scripts/relay_effect.py` → `cache/relay_effect/<交易日>.json`（固定昨日样本、分钟历史）→ `cache/relay_effect.json` 原子发布 → `/api/market/relay-effect` → 终端只读轮询。

- 默认仅昨2板以上，昨首板单独对照；失败股票不移出样本，晋级不改变分组。
- 东财 f6 单位元；腾讯 p[37] 单位万元（已用公开行情 p[35] 成交额交叉核实），统一发布亿元。行情时间来自源，不使用抓取时间冒充。
- 近15分钟为同一连续交易时段的累计成交额差；目标基准容差60秒，开盘前15分钟无窗口。午休、跨日、累计额回退、缺失不计算。每分钟只保留最新行情，重复执行不增加同一分钟样本。
- 当前行情最多延迟180秒；午休/盘后锚定11:30/15:00。页面定时判定整个快照是否过期，过期暂停榜单而保留最后读数。
- 当前封板需要当前涨停池、新鲜盘口且有买一无卖一的证据；当日曾封板不作为当前封板。未确认状态为空。未封板不自动标作炸板。
- 汇总显示各类有效覆盖数；缺失不作零。活跃走强要求今日涨幅为正、窗口涨幅增加；活跃走弱要求窗口涨幅减少；以区间成交额排序。
- 当前成交额非净流入、非实际收益、非昨日同期量比。分段成交额按相邻快照区间展示。

首次启用需等待交易时段内数据采集成功，15分钟窗口随后形成；不得补造历史记录。运行中的开发服务器通过 routes.ts 读取接口，独立 Python 服务需在维护窗口重启以加载新增路由。正常采集脚本每次执行会自动加载发布模块，无新增定时任务。无新快照时原赚钱效应模块正常运行。

验收：Python `tests/test_relay_effect.py` 验证固定样本、日期切换、缺值零值、午休、15分钟容差、重启；终端 `tests/relay-effect.test.tsx` 验证筛选、过期、展开。未执行打包/编译。有数据的浏览器验收使用临时接口模拟，结束后恢复真实接口；不写入生产数据目录。
