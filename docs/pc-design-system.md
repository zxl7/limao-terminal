# 狸猫终端 PC 端界面设计方案 v1.0

> 设计目标：把「移动端放大」的响应式页面，改造成真正的 PC 专业交易终端——在 4K / 宽屏下信息饱满、主次分明、机会与风险一眼可定位。
> 生效范围：以首页（盘中实时）为首批落地页，其余 20 页按同规范迁移。

---

## 1. 网站定位与核心目标

### 1.1 定位
**狸猫终端 = A 股短线情绪核心盯盘工作台**

- 用户：短线交易者、龙头战法实践者、情绪周期研究者。
- 场景：交易日盘中 09:15–15:00 高频盯盘；盘前/盘后做复盘与决策。
- 设备：主力设备为 27–32 英寸 4K PC 显示器，浏览器窗口常驻多标签。

### 1.2 核心目标
1. **一眼定调**：3 秒内看到市场整体情绪、资金方向、风险信号。
2. **机会前置**：把「可买方向 / 早鸟埋伏 / 主线热度」放在视线最先落到的位置。
3. **风险可见**：把「昨日反馈 / 连板天梯 / 跌停炸板」放在右侧或底部，作为辅助决策区。
4. **信息饱满**：4K 下不留下大片结构性空白；用密度和分区替代简单放大。
5. **减少滚动**：关键信息在一屏内可见；需要深入分析时才滚动。

### 1.3 用户明确的设计铁律
- **PC 优先**：禁止按移动端窄屏思路设计；禁大留白、禁为触屏牺牲密度。
- **涨红跌绿**：A 股语义，与欧美市场相反。
- **科创板不推**：688 / 689 代码在所有候选/推荐列表中过滤。
- **图表宽跟容器、高恒定**：禁 `w-full h-auto` 等比放大；hover 用图表 tooltip 浮层。
- **纯文本+简洁表格**：不渲染花哨 SVG 产物卡。

## 3. 整体视觉风格

### 3.1 设计语言
**高密度的专业金融终端**，而非消费级仪表盘。

- 气质：冷静、工具感、信息优先。
- 参考：Bloomberg Terminal / TradingView / 同花顺 PC 端的克制与饱满。
- 避免：大圆角、大阴影、emoji、装饰性插图、渐变色背景。

### 3.2 色彩系统
沿用现有 A 股语义色，作为唯一行情语义来源。

| 语义 | 色值 | 用途 |
|---|---|---|
| `up` | `#ee2500` | 上涨、改善、涨停、机会 |
| `up-soft` | `#ffe9e5` | 上涨/机会浅底 |
| `down` | `#0a8f3c` | 下跌、恶化、跌停、回避 |
| `down-soft` | `#e3f4ea` | 下跌/回避浅底 |
| `rec` | `#8b5cf6` | 可买 / AI 推荐 |
| `rec-soft` | `#f1ecfe` | 推荐浅底 |
| `lead` | `#e8940a` | 涨停标杆龙 |
| `lead-soft` | `#fdf3e0` | 标杆浅底 |
| `warn` | `#0d9488` | 退潮预警、风险 |
| `warn-soft` | `#dcf1ef` | 预警浅底 |
| `mid` | `#3b82c4` | 中性、情绪分 3–6 |
| `mid-soft` | `#e6f0fa` | 中性浅底 |
| `bg` | `#f2f3f6` | 工作区背景 |
| `card` | `#ffffff` | 卡片背景 |
| `line` | `#e7e8ee` | 卡片边框、分隔线 |
| `line-faint` | `#f0f1f5` | 表格行分隔 |
| `line-strong` | `#d3d5dd` | 强分隔 |
| `txt` | `#16161a` | 主文字 |
| `sub` | `#666a76` | 次要文字 |
| `head-bg` | `#1c2130` | 顶栏/侧栏深底 |
| `head-txt` | `#eef1f7` | 深底上主文字 |
| `head-soft` | `#9aa4b8` | 深底上次要文字 |
| `head-up` | `#ff6b52` | 深底上涨色（提亮） |
| `head-down` | `#34d399` | 深底下跌色（提亮） |

**用色纪律**：
- 深底仅用于顶栏、侧栏、右 rail 顶部；工作区卡片必须用浅底。
- 红色仅点睛（价格、关键机会、风险句）；禁止大面积飘红。
- 浅底色调仅用于状态徽标、行底、退潮预警通栏。

### 3.3 字体系统
- 主字体：`-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Microsoft YaHei', sans-serif`
- 数值字体：`'SF Mono', Menlo, ui-monospace, monospace`（等宽 + tabular-nums，避免刷新时列宽跳动）

| 层级 | 字号 | 字重 | 行高 | 用途 |
|---|---|---|---|---|
| 页面大标题 | 18px | 600 | 1.3 | 页面名 |
| 卡片标题 | 14px | 600 | 1.3 | 卡片头 |
| 区段标签 | 10.5px | 600 | 1.2 | 三栏区标题（大写/字间距） |
| 正文 | 13px | 400 | 1.4 | 列表、说明 |
| 辅助文字 | 12px | 400 | 1.3 | 标签、时间、脚注 |
| 数值 | 13–15px | 500–700 | 1 | 价格、涨跌幅、情绪分 |
| 大数值 | 22–28px | 600 | 1 | 情绪分、关键 KPI |

### 3.4 间距系统
以 4px 为基准单位，所有间距均为 4 的倍数。

| token | 值 | 用途 |
|---|---|---|
| `space-1` | 4px | 行内间距、徽标内边距 |
| `space-2` | 8px | 卡片内小间距、表格行内 |
| `space-2.5` | 10px | 卡片 padding |
| `space-3` | 12px | 卡片之间、区内卡片间距 |
| `space-4` | 16px | 区与区之间 |
| `space-5` | 20px | 页面边距 |
| `space-6` | 24px | 大模块间距 |

**用间距纪律**：
- 同一区内卡片间距 12px；不同区之间 16px。
- 卡片内 padding：10–12px；高密度表格行高 32px。
- 禁止 24px 以上的卡片间距——那是移动端留白，不是 PC 密度。

### 3.5 圆角与阴影
- 卡片圆角：`8px`
- 徽标/按钮圆角：`4px`
- 侧栏/顶栏：`0px`（紧贴边缘）
- 阴影：默认无阴影；hover 悬浮卡片用极淡阴影 `0 2px 8px rgba(0,0,0,0.06)`。

### 3.6 布局结构

#### 3.6.1 全局骨架
```
┌─────────────────────────────────────────────────────────────────────┐
│  左侧导航栏 (220px)  │  顶部状态条 (46px, 全宽)                       │
│                     ├─────────────────────────────────────────────────┤
│                     │  主工作区 (flex-1)  │  右侧辅助 rail (300–360px)  │
│                     │                   │  （自选/异动/快讯）           │
└─────────────────────┴───────────────────┴─────────────────────────────┘
```

- **左侧导航栏**：固定 220px，深底，五段分组。仅图标 + 文字，不展开子菜单。
- **顶部状态条**：指数、情绪、广度、时间、健康。全局可见。
- **主工作区**：内容核心，占满剩余宽度。
- **右侧辅助 rail**：仅在 ≥3xl（1920px）显示，用于自选、异动、快讯等个性化实时信息。

#### 3.6.2 首页（盘中实时）分区

```
┌─────────────────────────────────────────────────────────────────────┐
│ MoodBar 指挥条（指数 + 情绪 + 广度 + 时间）                         │
├───────────────────┬───────────────────────────┬─────────────────────┤
│ 机会区 20%        │ 主工作区 50%               │ 风险辅助区 30%      │
│ · 早鸟埋伏        │ · 核心标的宽表            │ · 昨日反馈         │
│ · 主线热度        │ · 板块资金流向            │ · 连板天梯         │
│                   │ · 短线精灵信号            │ · 极值名单         │
├───────────────────┴───────────────────────────┴─────────────────────┤
│ 前瞻补充区：次日预期 (50%) │ 板块增减 (50%)                          │
└─────────────────────────────────────────────────────────────────────┘
```

- **通栏**：MoodBar + EbbBanner（退潮预警）。
- **三栏**：机会 / 主工作 / 风险，宽度比 20:50:30。
- **辅区**：下方两栏，不抢占主区空间。
- **右侧 rail**：自选/异动（≥3xl 显示）。

#### 3.6.3 响应式策略
PC 优先，向下适配，而非移动端优先放大。

| 断点 | 宽度 | 布局 |
|---|---|---|
| `<lg` (<1024px) | 平板/小屏 | 隐藏侧栏，顶部回退导航；单栏纵向 |
| `lg` (1024–1279px) | 小桌面 | 侧栏 220px；实时页双栏（机会+主工作） |
| `xl` (1280–1535px) | 桌面 | 侧栏 220px；实时页三栏；风险区完整显示 |
| `2xl` (1536–1919px) | 大桌面 | 三栏比例 20:50:30；卡片内信息密度提升 |
| `3xl` (1920–2559px) | 2K | 三栏 + 右侧 rail 300px；主工作区内部可再分多列 |
| `4xl` (≥2560px) | 4K | 三栏 + 右侧 rail 360px；主工作区可 4 列内嵌网格 |

**关键原则**：
- 4K 下不是把 1 列卡片等比放大到 5 列，而是让内容区真正承载更多信息。
- 右侧 rail 只在宽屏出现，不挤占 ≤1920px 的主区。

### 3.7 组件规范

#### 3.7.1 卡片（Card）
- 白底、1px `line` 边框、8px 圆角。
- padding：`10px 12px`。
- 标题行：14px 600，下方 8px 间距。
- 标题右侧可接 `CardBadge`。

#### 3.7.2 KPI / 关键指标
- 大数值 22–28px + 等宽字体。
- 标签 12px sub。
- 辅助说明一行，超出截断或换行。

#### 3.7.3 表格
- 表头 12px sub，行高 32px。
- 单元格左对齐；数值右对齐。
- 行分隔用 `line-faint`，hover 行用 `bg-bg`。
- 长名称最大宽度限制，tooltip 浮层显示完整。

#### 3.7.4 列表
- 行高 28–32px。
- 左侧用小色点/色块表示 tone。
- 标签与数值之间留足够间隙。

#### 3.7.5 徽标（Badge）
- 11px 字号，4px 圆角。
- 空心描边为主，实心仅用于极高优先级。

## 4. 主要页面布局方案

### 4.1 首页（盘中实时）

#### 4.1.1 顶栏（MoodBar）
```
[品牌] [指数1 价格 涨幅] [指数2 价格 涨幅] [指数3 价格 涨幅]  [情绪 分数 标签]  [涨跌家数 涨|平|跌] [涨停 跌停 炸板 封板率] [更新时间 健康灯]
```

- 指数：价格用 `num` 字体，涨幅用 tone 色。
- 情绪分：大数字（24px），分数≥7 红、3–6 蓝、<3 绿。
- 广度：涨跌家数并排，涨停红、跌停绿、炸板青。
- 右侧：时间 + 健康指示灯（新鲜为绿点）。

#### 4.1.2 三栏区
**机会区（左，20%）**
- 早鸟埋伏：板块列表，每行「板块名 + 龙头 + 涨幅 + 催化」。
- 主线热度：top5 题材，每行「题材名 + 龙头 + 涨停数 + 龙头涨幅」。

**主工作区（中，50%）**
- 核心标的宽表：28 只 leaders 按板块聚合，表格列「板块 / 代码 / 名称 / 涨幅 / 连板 / 催化」。
- 板块资金流向：inflow top / outflow top 并排或上下。
- 短线精灵信号：时间序列列表，最新在上。

**风险辅助区（右，30%）**
- 昨日反馈：前日候选今日涨跌分布。
- 连板天梯：高度梯队图/表，从 1 板到最高板。
- 极值名单：跌停池 / 炸板池，过滤 688/689。

#### 4.1.3 前瞻补充区
- 次日预期：东财次日预期列表，板块 + 个股 + 理由。
- 板块增减：板块异动增加/减少榜。

#### 4.1.4 右侧 rail（≥3xl）
- 自选：用户关注票的价格/涨幅速览。
- 异动：盘中最新脉冲信号（5 条以内）。
- 快讯：财联社/选股宝实时新闻标题（滚动或列表）。

### 4.2 题材轮动页
- 顶部：情绪周期阶段 + 当前主线方向。
- 主区：题材轮动的时序图 + 当前强度表。
- 右侧：相关龙头列表。

### 4.3 资金流向页
- 主区：板块资金流向桑基图 / 堆叠条形图。
- 下区：个股资金净流入表。

### 4.4 情绪周期页
- 顶部：情绪分 5 日轨迹（折线图）。
- 主区：情绪因子分解表。
- 下区：历史周期节点标注。

### 4.5 交易战绩 / AI 台账 / 回测页
- 主区：净值曲线 + 关键指标 KPI strip。
- 下区：交易记录表 / 回测报告列表。

## 5. 交互规范

### 5.1 悬停（Hover）
- 表格行 hover：背景 `bg-bg`。
- 卡片 hover：极淡阴影，无位移。
- 数值 hover：tooltip 浮层显示完整信息（禁止在图表下方加静态读数行）。

### 5.2 滚动
- 长名单在卡片内部滚动，不撑开整页。
- 卡片最大高度按视口比例限制（如 `max-h-[38vh]`）。
- 滚动条使用系统默认，不做自定义重绘。

### 5.3 数据刷新
- 数据 30s 一轮；变化字段用短暂高亮（`transition-colors duration-500`）提示。
- 陈旧数据：健康灯变灰，数值显示「—」，不伪造数据。

### 5.4 空态与错误
- 空数据：显示「暂无数据」或「—」，不占大块空白。
- 加载：骨架屏优于转圈；局部加载不阻塞整页。
- 错误：红色提示条，不崩溃。

## 6. 4K 屏幕特殊处理

### 6.1 避免「放大感」的三条铁律
1. **不要等比放大卡片**：4K 下卡片数量应增加，或单卡片承载更多字段，而不是把 1 张卡片放大到 4 倍。
2. **固定字体上限**：正文不超过 15px；大数值 24–28px。禁止因为屏幕宽就放大字号。
3. **引入辅助 rail**：≥1920px 时右侧 300–360px rail 显示自选/异动/快讯，填满原本空出的边缘。

### 6.2 视口缩放适配
- Windows/macOS 在 4K 上常开启 150% / 200% 缩放，有效 CSS 宽度可能只有 1920px 甚至 1280px。
- 因此布局必须按**有效 CSS 宽度**响应，而非物理像素。
- 核心信息在 1280px 有效宽度下仍应完整可用。

## 9. 分区原语（全站统一 · 2026-09-16 落地）

一致性靠**共用组件**而非约定：所有页面的主工作区骨架都来自 `@/shared/ui`，页面侧只声明「占多大宽度」，不写断点字面量。

### 9.1 两套原语，分工不可互换

| 原语 | 语义 | 何时用 | 列/栏行为 |
|---|---|---|---|
| `Board` + `BoardItem` / `BoardWide` | **等权网格** | 并列卡片多、无主次（如指标卡群） | 1 → 2(lg) → 3(xl) → 4(3xl) → 5(4xl) 列 |
| `ZoneRow` + `Zone` | **任务导向分区** | 有主次（主工作区 / 辅助区 / 风险区） | `<xl` 纵向单栏；`≥xl` 按百分比横向分栏 |

`ZoneRow` 内固化了两个不可省的约束：`xl:items-start`（否则 `stretch` 把空洞从页级搬到栏级）、各栏 `min-w-0`（防长表格/长数字溢出）。

### 9.2 页面分区的标准范式

```
根容器 flex flex-col gap-3
├── 概览 / Hero 卡通栏            ← 全局定性，层级最高（无 Zone 标签）
└── ZoneRow
    ├── Zone 主工作区    xl:w-[60%~68%]   ← 宽表 / 图表，内容最重
    └── Zone 辅助区      xl:w-[32%~40%]   ← 归档 / 警示 / 次要清单
```

- **主工作区一律给宽表或图表**：多列宽表在 4K 下需要横向空间，这是「利用横向」而非「留白」。
- **辅助区放归档/警示**（历史期次、存档缺口、推送失败）：它们天然窄，占满一整行才是浪费。
- **窄屏自动退化**：`<xl` 所有 `Zone` 变纵向单栏，不需要额外写媒体查询。

## 10. 外壳可见性契约（2026-10-18 立）

### 10.1 三段式外壳的实际宽度

| 视口 | 左侧栏 | 右侧 rail | 顶部兜底 tab | 主区 |
|---|---:|---:|---:|---:|
| ≥1920（`3xl`） | 220 | 320 | 隐藏 | 视口 − 540 |
| 1280–1919（`xl`–`2xl`） | 220 | 隐藏 | 隐藏 | 视口 − 220 |
| 1024–1279（`lg`） | 220 | 隐藏 | 隐藏 | 视口 − 220 |
| <1024 | 隐藏 | 隐藏 | 显示 | 视口 |

**推论**：页面断点算的是**视口宽**，而内容区只有「视口 − 540」。因此 `3xl` 下的 4 列网格，单卡实际约 330px（低于 `Board` 自己声明的 380–640 区间）。若在 1920 上觉得卡片挤，优先调页面内分栏比例，⛔ 不要去改 `Board` 的断点阶梯（会影响无 rail 的 1440 场景）。

### 10.2 ⛔ 可见性写法唯一安全姿势

`display` 与 `flex-direction` 在 Tailwind v4 产物中都是「裸类排在响应式变体之后」⇒ 裸类在所有宽度生效。新写任何「窄屏隐藏 / 宽屏显示」必须是**两个互斥媒体查询**：

```tsx
// ✅ 安全
'max-lg:hidden lg:flex'   'max-3xl:hidden 3xl:flex'   'max-lg:flex lg:hidden'
// ⛔ 会静默失效（且测试可能全绿）
'hidden lg:flex'          'hidden 3xl:flex'            'lg:hidden flex'
```

守卫：`tests/tailwind-class-conflict.test.ts`（5 项）。
